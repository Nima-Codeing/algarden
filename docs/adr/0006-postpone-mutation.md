# 0006. 突然変異を v1 から外し、v1.1 に回す

- 状態：採用
- 決定日：2026-07-28

## 背景

5月の設計では、低い確率で正八面体や放射状の形が生まれる「突然変異」を v1 に入れる予定だった。その後、毛玉を作るために延焼（[0004](0004-forest-fire.md)）を入れると決めた。

## 検討した案

### 突然変異と延焼の両方を v1 に入れる

- どちらも「毎回ちがう形が生まれる驚き」を担っていて役目が重なり、片方の効果がもう片方に埋もれる。実装の量も倍になり、v1 が完成しないおそれが一番大きくなる。

### 延焼を外し、突然変異だけで v1 を作る

- 参考にした画像の毛玉に届かない。

### 突然変異の列だけ残し、生成のコードは書かない

- 使われない列が残ると、設計の意図が読めなくなる。戻すときはマイグレーション1本で済むので、残しておく利点がない。

## 決定

突然変異は v1 に入れず、v1.1 で見直す。突然変異のための列も消す。

## 結果

- 【当初】：決めたときに見込んでいたこと
- 【年-月】：後から分かったこと（分かった時期）

### メリット

- 【当初】設計の複雑なところの多くが突然変異にあったので、それがまとめて消えた。たとえば、設計図を JSON で持つ方法や、変異したノードを着火点の候補から外す例外の処理である。
- 【当初】延焼のために PlantEdge テーブルが v1 に残るので、突然変異を後から足すときの受け皿はすでにある。

### デメリット

- 【当初】正八面体のような幾何学的な形は、v1 では出ない。
