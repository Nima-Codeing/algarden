# 0001. フロントエンドを Vite + React の SPA にする

- 状態：採用
- 決定日：2026-03-25

## 背景

AlGarden は、ネットワークが成長する瞬間を体験することで、楽しく作業できるようにすることを軸に開発している。フロントエンドを選ぶときの前提は、次の3つだった。

- MVP を作るため、コストを抑えたい。
- 画面がスムーズに動くことが、UX を高めると考えている。
- スマホのアプリとしてあるとかなり便利で、自分も欲しい。そのためモバイル対応をしたい。まずはレスポンシブ対応をして、その先でアプリを作ることを目標にしている。

今回が初めての技術選定だった。

## 検討した案

### ページ構成

SPA・MPA・SSR / SSG の中から選んだ。

- MPA：リクエストのたびにページの再読み込みが入り、UX を下げる要因になると考えた。
- SSR：サーバーで HTML を動的に作って送った後に、JS を送る。最初は HTML だけが届くぶん表示が速く、クローラーも読めるので SEO に強い。
- SSG：ビルドの時点で各ページの HTML を作っておくので、SEO に強い。
- SSR / SSG は SPA と MPA のいいとこ取りで、性能では一番良い。ただ、学習コストと開発コストがほかの構成より高く、MVP を作るのには向いていないと考えた。

### フレームワーク・ライブラリ

SPA にしたので、React・Vue.js・Angular の中から選んだ。

- Angular：学習コストがほかより高く、個人開発のような小規模なシステムには向かない。また日本語の記事や Q&A が少なく、自分が扱えるかを考えたとき、React の方がまだ扱えそうだった。開発を速く進める観点で、向いていないと考えた。
- Vue.js：学習コストが低いことが強み。ただ、モバイル対応をしたかったので、学習コストが少し上がっても React を選んだ。

### ビルドツール

Create React App・Webpack・Vite の中から選んだ。

- Create React App：React 公式も非推奨としている。
- Webpack：Vite の方が、開発サーバーの起動が速い。

## 決定

フロントエンドは、Vite + React の SPA にする。

- SPA：UX を下げない。当時の追加機能案と MVP の機能には SEO 対策が要らず、コストもほかの構成と比べてまだ抑えられる。
- React：今回 TypeScript を学んだ。スマホアプリを追加機能として作るとき、React Native なら TypeScript で開発できる。web で React を使っておけば、Hooks などの知識もアプリ開発で使える。そのため React が一番良いと考えた。
- Vite：開発サーバーの起動が速く、React を使うときのビルドツールのデファクトスタンダードでもある。

当時は SEO が必要になるかわからなかったため、引き算の美学の考え方から、簡潔さと開発コストの低さを取った。
