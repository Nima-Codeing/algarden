# 0003. ORM を Prisma にする

- 状態：採用
- 決定日：2026-03-25

## 背景

フロントエンドは React + Vite、バックエンドは NestJS にすると決まっていた。そのうえで、DB とバックエンドの間で使う ORM を選んだ。

Prisma・Drizzle・TypeORM はどれも使ったことがなかったので、調べた範囲で選んだ。

## 検討した案

### Prisma

- スキーマファーストで、高度な抽象化で SQL をあまり気にせずに開発できる。
- 型安全性が高いので、DX が高い。

### Drizzle

- SQL ファーストで、生の SQL を書いている感覚で使える。Prisma にはない RIGHT JOIN などもあり、より複雑な SQL を書ける。
- ただ、MVP の時点では DB のテーブルが少なく、複雑な SQL を作る予定もなかった。MVP の非機能要件に、パフォーマンスチューニングも入れていなかった。学習コストも、Prisma の方が低くて済む。

### TypeORM

- デコレータ等の思考が似通っているため、NestJS と一緒によく使われる。
- 型安全性は、Prisma の方が高い。

## 決定

ORM は Prisma にする。

- スキーマファーストで、簡単なコードでクエリを書けるので分かりやすい。
- 型安全性が非常に高く、DX も高い。開発のしやすさと、バグの見つけやすさを取った。
