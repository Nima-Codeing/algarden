# 0007. ノードの座標は、サーバーで d3-force を使って計算する

- 状態：採用
- 決定日：2026-08-04

## 背景

それまでノードの位置は、親からの角度と距離で持っていた。延焼（[0004](0004-forest-fire.md)）でループができると、親子ではないエッジが生まれ、角度と距離では位置を決められない。

## 検討した案

### ブラウザで計算する

- リロードのたびに配置が変わり、育てた庭が同じ形に見えなくなる。

### 毎回、全ノードを動かす

- Todo を完了するたびに、庭全体の形が組み変わってしまう。

### 新しいノードだけを動かし、ほかはすべて固定する

- 混み合った場所に生えると、周りのノードが動かないため重なってしまう。

## 決定

PlantNode に x / y を持たせ、サーバー（NestJS）で d3-force を使って計算し、DB に保存する。動かすのは新しいノードから2ホップ以内だけで、それ以外のノードとルートは固定する。

## 結果

- 【当初】：決めたときに見込んでいたこと
- 【年-月】：後から分かったこと（分かった時期）

### メリット

- 【当初】リロードしても配置が変わらず、ブラウザの性能にも左右されない。

### デメリット

- 【当初】2D から 3D へ移しやすいように角度と距離で持っていたが、その利点は捨てた。今作るものを表現できることを優先した。
- 【2026-10】計算が遅い。ノード1つ分の計算に、300ノードの庭で約0.72秒、1000ノードの庭で約3.1秒かかる。動かないノードにかかる力まで毎回計算していることが原因で、改善は MVP の後に回した（[#131](https://github.com/Nima-Codeing/algarden/issues/131)）。
