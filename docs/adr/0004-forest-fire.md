# 0004. 庭の成長に Forest Fire の延焼を入れる

- 状態：採用
- 決定日：2026-06-30

## 背景

庭は、Todo を完了するたびにノードが増えていくネットワークである。目指す見た目は、参考にしたネットワークの画像のように、細い蔓・ハブ・密な毛玉が混ざった形だった。それまでの成長は、新しいノードが親を1つだけ選ぶ木構造だった。木にはループができないため、ループの束である毛玉は作れなかった。

## 検討した案

### 木構造のまま、毛玉は突然変異に任せる

- 突然変異は 3% の確率でしか起きない。毛玉は画像の主役なので、それでは数が足りない。

### BA モデル・空間ネットワーク

- Forest Fire と並べて生成し、見比べた。蔓・ハブ・毛玉の違いを1つのモデルで出せたのは、Forest Fire だけだった。

## 決定

新しいノードは、着火点（親）と1本のエッジでつなぐ。さらに一定の確率で延焼を起こし、着火点の隣のノードから確率で燃え広げる。新しいノードから、燃えたノードにもエッジを張り、ループを作る。

## 結果

- 【当初】：決めたときに見込んでいたこと
- 【年-月】：後から分かったこと（分かった時期）

### メリット

- 【当初】延焼の起きやすさと燃え広がりやすさの確率を変えるだけで、毛玉の数と濃さを調整できる。

### デメリット

- 【当初】ノードのつながりが、親子の1本では表せなくなった。延焼でできたエッジは PlantEdge テーブルに入れ、親子のエッジは parentId と PlantEdge の両方に持つ。
- 【2026-07】ループができるので、親からの角度と距離でノードの位置を決める方式が使えなくなった（[0007](0007-d3-force-coordinates.md)）。
